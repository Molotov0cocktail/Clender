# Clender 悬浮快捷对话、双字号与日历间距提案

## 目标

- 将今日悬浮窗改为无标题、无日期标题的简洁事项面板，默认沉在普通窗口底层，并可在运行时切换置顶。
- 在悬浮窗底部提供复用主 AI 当前对话的快捷输入，不显示模型正文，但保留完整主对话历史和日程操作能力。
- 支持除输入区和操作按钮外的全窗拖动、自定义边缘/四角缩放，以及双击事项直接编辑。
- 对正在进行与下一批事项做稳定、主题可辨识的特殊显示。
- 将悬浮透明度范围扩展为真实 0%–100%。
- 修复周/日视图时间标签与网格、marker、事项块重叠。
- 新增彼此独立的应用字号和悬浮窗字号设置，均支持 8–20px、1px 步进、保存后即时生效。
- 通过集中字号角色和静态扫描防止字号漏改、错改、重复硬编码及 point/pixel 混用。

## 非目标

- 不增加新的 Provider 协议、模型 API、依赖或 SQLite schema。
- 不为悬浮 AI 建立第二套 Conversation、HTTP 或日程执行逻辑。
- 不在悬浮窗显示 AI 的回复正文、Thinking 或 Token 信息。
- 不为 AI 删除或批量操作增加新的确认步骤；继续沿用主 AI 权限。
- 不持久化悬浮窗置顶状态；每次启动都回到窗口底层。
- 不修改 30px 每小时的时间轴密度，不重做三栏主窗口比例。
- 不控制 Windows 原生窗口标题栏等操作系统绘制字体。
- 不读取、迁移或修改真实 `data/`、`dist/data/`、API Key、数据库或对话内容。

## 用户与运行场景

- Windows 桌面用户把悬浮窗作为桌面日程面板；普通状态不遮挡其他应用，需要时临时置顶。
- 用户从悬浮窗快速输入自然语言，消息应出现在主界面当时活动的对话中；即使随后切换会话，响应仍写回发起会话。
- 用户可能在 100%–200% DPI、Light/Dark、8px 或 20px 字号、窄周视图和多屏环境中使用。

## 功能需求

### 悬浮窗外壳

- 使用无边框顶层窗口，不显示系统标题栏、关闭按钮或内部日期标题。
- 默认使用 `Qt.WindowStaysOnBottomHint`；底部输入行右侧提供置顶切换按钮，在 bottom/top 间互斥切换。
- 置顶只存在于内存，不写 `config.json`；重启恢复 bottom。
- 左键可在列表、空态和普通背景上按拖动阈值移动窗口；输入框、置顶按钮和缩放边缘不触发拖动。
- 保留几何记忆和自定义边缘/四角缩放，最小尺寸下输入区与事项仍可用。
- 0% 透明度表示完全不可见；用户从主应用设置恢复。

### 事项与编辑

- 单击事项不打开对话框；双击有效事项直接打开编辑表单。
- 保存经 `EventService` 验证并刷新月/周/日、日程安排和悬浮窗；取消、无效 ID、校验或写入失败不发 `data_changed`。
- 编辑允许 reminder/timespan 双向转换；转换为 reminder 时显式清空 `end_time`，转换为 timespan 时必须提供有效结束时间。
- 悬浮窗不新增删除入口。

### 当前与下一事项

- timespan 的当前区间为 `start <= now < end`。
- reminder 的 `estimated_duration > 0` 时当前区间为 `start <= now < start + duration`；为 0 时只在开始分钟内视为当前。
- 所有同时满足当前条件的事项均为 current。
- 所有开始时间等于最早未来开始时间的事项均为 next；有 current 时仍标记 next。
- 端点、跨日、并列、无 next 和坏旧数据必须确定性处理；状态至少每分钟更新。

### 悬浮 AI

- Enter 将非空文本提交给主页面 `AIChatWidget` 的当前 Conversation；悬浮窗不复制网络实现。
- 用户消息、Thinking、操作结果和回复按主聊天现有规则写入该 Conversation 并保存。
- 请求绑定提交时 Conversation ID；提交后切换会话不会串写。
- 主聊天与悬浮输入共享单个在途请求；在途期间两个发送入口均禁用，不排队。
- 悬浮窗只展示短状态：处理中、已修改日程、未修改日程、受限错误摘要；不显示 AI 正文。
- 只有成功 add/update/delete 才触发统一 `data_changed` 刷新。

### 双字号

- `app_font_size_px` 控制主窗口、日历、日程安排、AI、应用/AI 设置、事件表单/详情、菜单、消息框和工具提示。
- `floating_font_size_px` 只控制悬浮窗事项、状态、输入和置顶按钮；不被应用字号覆盖。
- 两者默认 13px，合法值为非 bool 整数 8–20；旧配置缺字段或非法值回退默认。
- 设置界面为两个滑块与 SpinBox 联动控件，范围 8–20、步进 1；保存完整 JSON 后立即生效。
- 标题、正文、辅助文字保留语义层级，但每个最终角色值均限制在 8–20px。
- 所有字体数字、角色、像素转换集中管理；生产模块不得残留裸 `font-size: Npx`、数字 QFont 大小或重复字号常量。

### 周/日时间轴

- 使用当前 Canvas 字体的 `QFontMetrics` 计算可容纳 `00:00` 的 gutter。
- 时间标签在 gutter 内右对齐，标签右缘与网格/marker/事项左缘至少相隔 8px。
- 周表头 spacer、网格起点、事件列几何、命中区域共享同一 gutter 契约。
- 保持 30px 每小时；20px 下短块可仅显示标题、marker 或省略，不扩大主窗口比例。

## 输入、输出与依赖

- 输入：完整 JSON 配置、Event、当前 Conversation、Qt 鼠标/双击/键盘事件、系统当前时间。
- 输出：原子保存的双字号配置、事件 CRUD、Conversation JSON、窗口 geometry、UI 信号和绘制区域。
- 依赖：现有 PyQt5、requests、SQLite 和标准库；不新增依赖。

## 约束与假设

- UI → service/pure logic → data/model 依赖方向不变；所有事件写入经过 `EventService`。
- HTTP 继续只在 `AICallThread` 中执行，Qt 控件只在主线程更新。
- 测试使用临时配置/数据库、mock 网络和 offscreen Qt，不读取真实运行数据。
- 既有已暂存 `.github/workflows/test.yml` 是用户改动，本轮保留但不提交。

## 成功标准与验收

1. 悬浮窗无两个旧标题行，能从列表/空白拖动并从边角缩放；输入和置顶按钮保持可交互。
2. 启动为置底，切换置顶后 geometry/可见性不丢失；重启契约仍为置底。
3. 双击事项可编辑并真实完成类型转换；单击不打开；成功后所有相关视图刷新。
4. 悬浮输入写入主页面发起时的 Conversation，主聊天可见完整响应，悬浮窗只见短状态。
5. current/next 在端点、并列、跨日和分钟推进时正确显示，Light/Dark 均可辨识。
6. 透明度 0、100 以及非法值回退符合契约。
7. 应用/悬浮字号可分别保存 8–20px 并即时生效，互不串扰；静态审计无字号硬编码遗漏。
8. 周/日时间文字与网格、marker、事项至少有 8px 几何间距。
9. 聚焦/全量测试、导入、offscreen、Light/Dark 8/20px 截图、`build.py --check`、完整 PyInstaller、隔离 exe 冒烟全部通过。
10. `dist/data/` 构建前后只读快照完全一致；提交不含用户 staged CI 改动、秘密、数据或生成物。

## 假设与开放问题

- 用户已确认所有产品决策，无阻塞性开放问题。
- Windows 对 `WindowStaysOnBottomHint` 的细节仍需真实 exe 人工/冒烟验证；若平台不支持，只记录风险，不擅自改为普通窗口。

# 项目现状与目标说明

## 项目概述

**Clender** 是一款基于 Python + PyQt5 构建的**智能日程管理桌面应用**，支持日间/夜间主题动态切换、系统托盘最小化，以及通过 AI（LLM）进行自然语言驱动的日程规划。

当前版本：**1.0**

---

## 当前状态分析

### 已实现的功能

- [x] **三栏布局主界面**：日历视图 + 事项管理面板 + AI 对话助手，通过 QSplitter 可拖拽调整比例
- [x] **月/周/日三种日历视图**：月视图为传统网格，周/日视图为连续时间轴 + 事件色块渲染
- [x] **手动事项管理**：支持提醒（reminder）和时间段（timespan）两种事件类型，提供添加/编辑/删除对话框
- [x] **AI 智能助手**：通过 OpenAI 兼容 API 调用 LLM，自动解析 JSON 操作指令（add/update/delete/reply）
- [x] **多对话管理**：可折叠的对话侧栏，支持新建、重命名、删除对话，对话历史持久化到 JSON 文件
- [x] **日间/夜间主题切换**：完整的两套配色方案（55+ 颜色语义变量），支持运行时动态切换
- [x] **系统托盘支持**：最小化到系统托盘，双击恢复，右键菜单退出
- [x] **数据库持久化**：SQLite 存储事件数据，支持 CRUD 操作
- [x] **AI 设置面板**：API 端点、密钥、模型、温度、上下文窗口、思考模式等完整配置
- [x] **Token 用量可视化**：实时进度条显示当前对话的 Token 消耗比例
- [x] **示例数据自动加载**：首次运行时自动注入当日示例日程
- [x] **打包构建脚本**：PyInstaller 单文件打包 + 桌面快捷方式创建

### 技术栈

| 层面 | 技术选型 |
|------|----------|
| UI 框架 | PyQt5 |
| 数据库 | SQLite（通过 sqlite3 标准库） |
| 网络请求 | requests |
| AI 集成 | OpenAI 兼容 API（支持 DeepSeek、OpenAI、Claude 等） |
| 打包 | PyInstaller（单文件 exe） |
| 配置管理 | JSON 文件 |

## 存在的问题

### 结构性问题

1. **模块耦合度过高**：各模块直接相互导入形成网状依赖（如 `ai_chat.py` 同时导入 `config`、`database`、`theme_manager` 三个模块），缺乏清晰的依赖层次
2. **单文件过大**：`ai_chat.py`（900行）、`calendar_widget.py`（446行）、`event_manager.py`（442行）承载了过多职责
3. **缺少抽象层**：UI 组件同时负责业务逻辑（如 `EventDialog.get_data()` 直接拼接 SQL 时间格式），View 和 Model 边界模糊
4. **硬编码严重**：系统提示词、颜色方案、模型能力映射表直接写在核心模块中
5. **全局状态依赖**：多处通过 `cfg_mod.load_config()` 和 `database.get_*()` 直接访问全局状态，缺乏依赖注入

### 稳定性问题

1. **缺少异常处理**：多个 try-except 块仅用 bare except 或空 pass，可能吞掉关键错误
2. **SQL 注入风险**：`update_event()` 使用字符串拼接构建 SQL（尽管参数化查询，但字段名拼接方式不够安全）
3. **类型不安全**：无类型注解，函数间传递 dict 作为数据契约，容易因字段缺失引发运行时错误
4. **线程安全**：`AICallThread` 直接访问主线程的 `_active_conv`，无锁保护
5. **数据库初始化时机**：`init_db()` 在模块导入时自动执行（database.py 末行），可能引发意外的副作用

### 扩展性问题

1. **新增事件类型困难**：事件类型 `reminder`/`timespan` 通过 if-else 硬编码在多处分发
2. **新增 AI Provider 困难**：模型能力表 `MODEL_CAPS` 硬编码，无插件式扩展机制
3. **UI 组件不可复用**：`WeekCanvas`/`DayCanvas` 作为内嵌类定义在 render 方法内，无法独立测试或复用
4. **主题扩展困难**：`theme_manager.py` 的颜色字典是扁平结构，新增语义变量需同时修改两套主题和所有引用处的 CSS 字符串
5. **测试覆盖率为零**：项目中无任何单元测试或集成测试代码

## 重构目标

在不改变现有功能和 UI 设计细节的前提下，完成以下重构：

### 目标一：提高模块化程度

- 明确模块间的依赖层次（数据层 → 业务层 → UI 层）
- 拆分过大文件（特别是 `ai_chat.py` 的 900 行）
- 提取公共基础设施（常量定义、数据模型、异常类型）

### 目标二：增强稳定性

- 为公共 API 添加类型注解（逐步引入）
- 统一异常处理策略
- 修复已知的线程安全和 SQL 注入问题
- 引入数据验证层

### 目标三：提升扩展性

- 事件系统抽象化（支持未来新增事件类型）
- AI Provider 接口化
- 主题系统结构化
- Canvas 组件提取为独立可测试类

### 非目标（暂不处理）

- 不改变现有 Python/PyQt5 技术栈
- 不添加新的外部依赖
- 不修改 UI 布局和交互方式
- 不改变数据库 schema
- 不引入异步框架（asyncio）
- 暂时不写测试（可作为后续 phase 的独立任务）

## 成功标准

1. ✅ 所有现有功能在重构后**完全不变**（回归测试手动对照）
2. ✅ 模块导入依赖形成**单向无环图**（数据层不依赖 UI 层）
3. ✅ `ai_chat.py` 拆分为 ≤ 300 行的多个模块
4. ✅ 公共函数/方法添加**类型注解**（至少包含核心数据流路径）
5. ✅ 消除所有**bare except** 和 **silent pass**
6. ✅ 配置文件与代码中**无硬编码的 API Key**（已泄露的 Key 需在文档中警示并建议轮换）

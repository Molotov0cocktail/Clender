# Clender 桌面体验修复与今日悬浮窗提案

## 目标

- 恢复 API Key 在 `config.json` 中的明文、原子持久化，避免 Windows Credential Manager 导致的保存失败。
- 修复历史 Thinking 展开时视口跳到底部的问题，使正文从点击标题下方向下展开。
- 保证同一 Windows 用户只能运行一个 Clender；再次启动时唤醒已有窗口。
- 修复周/日视图事件文字、标记和重叠事项互相遮挡，并让短提醒标记可点击查看详情。
- 新增可选的今日桌面悬浮窗，支持透明度、显示时间段、置顶、拖动缩放、详情查看和自动刷新。
- 将“规划阶段澄清不确定事项”“大规模修改使用独立子 agent”“Git 网络代理”写入工程规则。

## 非目标

- 不迁移现有 Windows Credential Manager 中的 API Key；升级后由用户在设置中重新保存。
- 不修改 AI Provider 协议、SQLite 既有字段或真实用户数据。
- 不让悬浮窗直接编辑事项；第一版只读展示详情。
- 不引入新的第三方运行依赖，不重做整套主窗口视觉风格。
- 不在自动化测试中访问真实 `data/`、`dist/data/`、API 或凭据库。

## 用户与运行环境

- Windows 单用户桌面应用，Python 3.12.4、PyQt5 5.15.11、SQLite、PyInstaller 单文件 exe。
- 主窗口可能隐藏在系统托盘；悬浮窗在主窗口隐藏时仍可独立显示。
- 配置位于开发态工程 `data/config.json` 或冻结态 exe 同目录 `data/config.json`。

## 功能需求

### 配置

- `load_config()` 只读取 JSON 并与默认值合并；`save_config()` 原子写入完整配置，包括 `api_key`。
- JSON 是 API Key 的唯一权威来源，不读取或迁移 Credential Manager，也不使用环境变量覆盖。
- 空 Key 可正常保存；坏 JSON 回退默认值；原子替换失败时旧配置不得被破坏。

### Thinking 展开

- 展开/收起时，点击的 Thinking 标题在视口中的垂直位置保持稳定。
- 新增正文出现在标题下方；新消息和首次进入对话仍可滚动到底部。
- 展开状态按 conversation ID 隔离；畸形链接不导致崩溃。

### 单实例

- 同一 Windows 用户只允许一个 Clender 进程承担应用实例职责。
- 第二次启动向首实例发送激活请求后以成功状态退出，不创建数据库、日志、主窗口、托盘或悬浮窗。
- 首实例从托盘恢复或置前；保留最大化状态；有活动模态窗口时优先置前该窗口。

### 周/日视图

- 两个重叠事项并排为两栏，多个重叠事项分配多个 lane。
- 重叠时间段使用边缘纹理/标记，非重叠时间段保持纯色，标记不得穿过文字。
- 当 lane 太窄时隐藏文字并保留可点击色块/标识；极短提醒只画可点击标识，不强行插入文字。
- 过多 lane 无法保证最小点击宽度时，将溢出 lane 合并为可点击摘要区域；用户选择具体事项后查看详情。
- 文字按可用宽高自适应：优先标题，空间足够再显示时间。

### 今日悬浮窗

- 设置中可启用；默认关闭。
- 默认显示 `08:00–22:00`，可调整起止时间；范围语义为过滤列表，不是完整时间轴。
- 包含与今天和所选时间段相交的时间段事项；提醒按其发生时刻过滤。
- 透明度 30%–100%，默认 90%；设置保存后立即生效。
- 始终置顶、可拖动、可缩放、无任务栏按钮，记忆位置和大小并保证重新落在可见屏幕。
- 单击事项打开只读详情；关闭按钮只隐藏，可从托盘恢复。
- 任何主程序内成功的手工或 AI 日程更改后立即刷新；跨午夜或睡眠恢复后自动切换日期刷新。

## 输入、输出与依赖

- 输入：现有 JSON 配置、Event 模型、EventService 查询结果、Qt 窗口/鼠标/本地 IPC 事件。
- 输出：原子更新后的 JSON、单实例激活消息、Canvas 几何与点击信号、今日事项列表和详情对话框。
- 依赖：仅现有 PyQt5、SQLite、标准库；单实例使用 `PyQt5.QtNetwork`。

## 约束与假设

- 用户明确接受 API Key 明文落盘及其风险。
- 不读取、删除或迁移现存 `Clender/API` Credential；`secret_store.py` 可从运行链路移除并删除源码/测试。
- 重叠布局的 lane 计算属于纯逻辑；Canvas 只做尺寸适配、绘制和命中测试。
- 悬浮窗通过 `MainWindow` 的统一数据变更编排刷新，不监听数据库文件。

## 成功标准与验收检查

1. 设置 API Key 后关闭并重新打开设置，值保持一致，JSON 包含 `api_key`。
2. 展开历史中间的长 Thinking 时标题屏幕位置基本不变，内容向下增长。
3. 启动第二实例时首实例从托盘恢复，第二实例快速退出且无第二托盘/悬浮窗。
4. 周/日视图的并发事项不互相覆盖；文字不与纹理相交；短提醒和聚合区域可点击查看详情。
5. 悬浮窗的开关、透明度、时间范围、位置大小持久化；手工/AI 数据变化后立即刷新。
6. 聚焦测试、全量 unittest、导入、Qt offscreen、Light/Dark 截图、环境检查、完整 PyInstaller 构建、双实例 exe 冒烟全部通过。
7. `dist/data/` 构建前后只读摘要一致；提交不包含真实数据、日志、数据库、对话、Key 或生成物。

## 已确认决策

- 不迁移旧凭据；用户重新保存 API Key。
- 单实例为同一 Windows 用户范围，二次启动置前已有窗口。
- Thinking 标题锚定，正文向下展开。
- 日历采用 lane 分栏、窄块无文字、短提醒可点击、过多重叠可聚合。
- 悬浮窗采用本提案列出的推荐规格，并在每次主程序数据更改后刷新。

## 开放问题

- 无阻塞性开放问题。实现中若发现现有契约无法满足上述验收，必须暂停并向用户确认。
